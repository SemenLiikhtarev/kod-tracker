# КОД — Конвейер Обработки Данных

Дашборд-трекер для конвейерной (последовательной) обработки данных, реализованный по ТЗ
`info/tz_data_tracker_KOD.txt`. Заказы приходят письмами (Яндекс.Почта), файлы лежат на
Яндекс.Диске, этапы передаются по конвейеру между исполнителями по механике «захвата».

## Что реализовано

- **Ролевая модель**: `manager` (руководитель), `executor` (исполнитель), `observer` (наблюдатель), вход по мок-Яндекс ID.
- **Механика конвейера и захвата**: пул задач → «Взять в работу» → «Завершить» → активация следующего этапа; «Вернуть в пул» / «Сбросить захват».
- **Фильтрация по типу обработки данных**: исполнитель видит и может взять только этапы своего навыка.
- **Уведомления** (UI-колокольчик + мок-Telegram): новый этап, задача взята, дедлайн горит (<2 ч), просрочка.
- **Фоновые воркеры**: монитор дедлайнов и очередь операций с ретраями.
- **Интеграции (мок-адаптеры)**: Яндекс.Почта (IMAP/SMTP), Яндекс.Диск (REST/WebDAV), Telegram Bot API.
- **Экраны**: авторизация, «Мои задачи», Канбан-доска конвейера, список проектов, карточка проекта (таймлайн + файлы Диска), аналитика, сотрудники, интеграции.
- **Аудит** действий (таблица `logs`) и журнал вызовов интеграций.

## Стек

ТЗ рекомендует Python (FastAPI/Django) + Celery. В этом окружении установлен только Node.js,
поэтому бэкенд реализован на **Node.js без внешних зависимостей**: HTTP-сервер из стандартной
библиотеки и встроенный модуль **`node:sqlite`** (Node ≥ 22.5). Архитектура полностью повторяет ТЗ:
API + бизнес-логика + фоновые воркеры (аналог Celery), реляционная БД (SQLite; схема в
`server/src/schema.sql` совместима с PostgreSQL), очередь с ретраями (аналог Redis/RabbitMQ).

- **Backend**: Node.js (`node:http`, `node:sqlite`, `node:crypto`), 0 зависимостей.
- **Frontend**: React 19 + Vite + TailwindCSS v4 (сине-белая дизайн-система из §5 ТЗ).
- **Логотип**: `info/logo_tracker_data.png` — в сайдбаре и на экране входа, как favicon.

## Требования

- **Node.js ≥ 22.5.0** (нужен встроенный `node:sqlite`; проверено на Node 24).
- npm.

## Установка и запуск

```powershell
npm run setup      # установка зависимостей фронтенда
npm run dev        # API на http://localhost:8000 + UI на http://localhost:5173
```

Открыть **http://localhost:5173**.

### Продакшн-режим (одним портом)

```powershell
npm run start      # собирает фронтенд и отдаёт UI + API на http://localhost:8000
```

### Прочие команды

```powershell
npm test           # тесты бизнес-логики конвейера (node:test)
npm run seed       # пересоздать демо-данные (--reset)
npm run dev:server # только API
npm run dev:web    # только Vite dev-сервер
```

## Основные эндпоинты API

| Метод | Путь | Описание |
| --- | --- | --- |
| POST | `/api/auth/login` | Вход (мок Яндекс ID) |
| GET | `/api/tasks/pool` | Пул задач исполнителя (по его навыкам) |
| GET | `/api/tasks/my` | Задачи исполнителя «в работе» |
| POST | `/api/tasks/:id/capture` | Взять в работу (транзакция, `BEGIN IMMEDIATE`) |
| POST | `/api/tasks/:id/release` | Вернуть в пул / сбросить захват |
| POST | `/api/tasks/:id/complete` | Завершить этап и активировать следующий |
| GET | `/api/tasks/board` | Канбан-доска по этапам |
| GET | `/api/projects/:id` | Карточка проекта (таймлайн, файлы, папки Диска) |
| POST | `/api/projects/:id/send-to-client` | Финализация: письмо клиенту через Яндекс.Почту |
| POST | `/api/dev/incoming-email` | Имитация письма «Новый заказ» |
| GET | `/api/analytics` | Аналитика и состояние очереди |
| GET | `/api/integrations/*` | Журнал и входящие/исходящие интеграций |

## Соответствие критериям приёмки (§10 ТЗ)

1. **Письмо с вложениями → проект + папки на Диске + файлы.** Кнопка «Получить новый заказ» (или `POST /api/dev/incoming-email`) и сценарий в `server/tests/pipeline.test.js`.
2. **Захват блокирует задачу для других.** Тест «захват задачи: второй исполнитель получает отказ».
3. **Завершение этапа → уведомление следующему исполнителю и задача в его пуле.** Тест «завершение этапа активирует следующий и уведомляет исполнителей».
4. **«Отправить клиенту» → письмо со ссылками на Диск.** Тест «полный проход конвейера и отправка результата клиенту».
5. **Сине-белая гамма и логотип.** Дизайн-токены в `web/src/index.css`, логотип в сайдбаре/на входе/во favicon.

## Нефункциональные требования (§8 ТЗ)

- **Конкурентный доступ**: захват выполняется в транзакции `BEGIN IMMEDIATE` (§8, аналог `SELECT ... FOR UPDATE`).
- **Отказоустойчивость интеграций**: операции с Диском и Почтой ставятся в очередь `queue_jobs`
  и ретраятся до `max_attempts`. Включить режим имитации сбоев: `SIMULATE_INTEGRATION_FAILURES=1 npm run dev:server`.
- **Безопасность**: токены подписываются HMAC-SHA256; секрет задаётся переменной окружения `KOD_SECRET`.
- **Адаптивность**: интерфейс рассчитан на десктоп и планшет; уведомления дублируются в Telegram.
